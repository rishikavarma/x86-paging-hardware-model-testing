We evaluate our approach using a qualitative evaluation showing that  1) we are capable of generating useful test cases for validation, and 2) the synthesis approach successfully finds the missing internal steps.
While a complete validation pipeline automatically performs all the steps outlined in \Cref{fig:validation-pipeline}, our current prototype requires manual intervention.

\subsection{Test Case Generation}

We evaluate whether using the reduced model to generate test cases yields useful programs that expose the desired hardware behavior.

\noindent\textbf{Methodology.}
%
We analyze our graph-based test case generator's reduction strategy to identify allowed test cases similar to existing hand-crafted Litmus tests designed to expose specific behavior of the memory subsystem~\cite{owens2009x86tso, sewell2010x86tso,alglave2011litmus,alglave2014herding}, particularly those involving the store buffer, since our model also includes it.
The classic store-buffer test~\cite{diySBlitmus} has two threads, each writing one location and then reading the other.
The outcome in which both reads see the initial value is allowed by x86-TSO but forbidden under sequential consistency. 

\noindent\textbf{Results.}
The generator would select two virtual memory addresses and generate a store and a load for each thread.
The test generator based on our reduced model would be capable of emitting the following program, which is identical to the classic store-buffer test~\cite{diySBlitmus}. 
%
\begin{verbatim}
  P0: Write(va1) = 1  |  P1: Write(va2) = 1
      Read(va2)       |   Read(va1)  
\end{verbatim}

\noindent\textbf{Discussion.} 
While this is a simple example, it shows that our reduction allows the generation of test programs similar to existing Litmus tests.


\subsection{Trace Synthesis}
% Purpose
We evaluate synthesis-based trace validation using two small case studies, one of which we designed so that no satisfiable solution is permissible under the model.

\noindent\textbf{Methodology.}
We set the initial state as follows:
The TLB is empty. The two-level page table has one valid page mapping, with the value 42 in the first byte. All other pages are not present. The page-walker contains an ongoing walk of the only present page in the page table. We assume this walk was started speculatively before test execution.

We then use the two observable program traces shown in \autoref{lst:eval:traces} as correctness constraints for the synthesizer. Case 1 accesses the page for which there is a present mapping, whereas case 2 accesses a page that is not present, but the test case reports an observed value.

% \begin{itemize}
    % \item The physical address space is minimized as per \Cref{sec:reduction}, with only seven addresses in total: 2 page-directory slots, 3 page-table-page slots, and 2 data pages.
    % \item Two-level paging is employed throughout the experiment.
    
    % \item The page-directory slot points at one page-table page, and only the first virtual address has a valid leaf entry mapping to a data page holding the value 42.
    
    % \item The completed page walk for the first address is pre-loaded in the core's walk list based on the simplifying assumption that the walk was completed before the test.
    
    % \item The sibling virtual address has no valid leaf entry, no pre-loaded walk, and its corresponding data page contains the value 99.
    % \item The TLB is empty at the start.
% \end{itemize}

\begin{lstfloat}[t]
\begin{lstlisting}[
  basicstyle=\ttfamily\scriptsize,
  xleftmargin=1.4em,

// Case 1: Successful memory read
memop_read core=0, vaddr=0x00000000, observed=42
// Case 2: Memory read that should not succeed
memop_read core=0, vaddr=0x00008000, observed=42
\end{lstlisting}
\caption{Observable program Traces for the satisfiable and unsatisfiable evaluation cases.}
\label{lst:eval:traces}
\end{lstfloat}


\noindent\textbf{Results.}
%
For the first case, the synthesizer successfully finds the missing internal step: filling the TLB with the value from the page walk (\texttt{tlb\_fill} in \autoref{lst:eval:completedtrace}). This step inserts the required entry into the TLB. Recall, a memory access is only possible if there is an entry in the TLB for the corresponding virtual page. The memory access can now read the memory cell and obtain the value 42, which matches the value observed in the trace.
In contrast, in the second case, which reads from a non-present page, there is no corresponding page walk to complete. Synthesis reports \emph{no solution}. Since the internal steps cannot update the page table, this could never have resulted in a successful memory access. 

\begin{lstfloat}[t]
\begin{lstlisting}[
  basicstyle=\ttfamily\scriptsize,

// internal step, filling the TLB.
tlb_fill   core=0, walk={
             virt=0x00000000, stage=complete,
             pte0=(0xfff00000 -> 0xfff01000, valid),
             pte1=(0xfff01000 -> 0xfff10000, valid)}
// TLB now contains the entry for virt=0x00000000
memop_read core=0, vaddr=0x00000000, observed=42
\end{lstlisting}
\caption{Completed Program Trace for Case 1.}
\label{lst:eval:completedtrace}
\end{lstfloat}

\noindent\textbf{Discussion.}
Despite this being a small example, it demonstrates the approach's feasibility as a proof of concept. The synthesizer successfully identified the missing internal steps.
