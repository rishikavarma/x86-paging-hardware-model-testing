\section{Test Harness}\label{sec:harness}
%% ============================================================

Executing tests on real hardware is not a trivial endeavor, as we must run the test case in supervisor mode while limiting potential interference from other programs and the rest of the operating system. 
Further, we must carefully eliminate interference from the test case itself; e.g., storing the result of a memory access adds additional memory accesses that might interfere with test execution.

Instead of writing our own test harness from scratch, we leverage Barrelfish's multikernel architecture~\cite{Baumann:2009:Multikernel} for our prototype. Specifically, it has isolated per-core kernels and runs system calls with interrupts disabled, limiting interference.
That lets us leverage Barrelfish's infrastructure for booting cores and memory management.
We integrate the test cases into the kernel. We write a small user-space driver that performs setup, coordinates among the cores, and then invokes the test case in the kernel via a system call.
At the end, we collect the results: the observed outcome of the memory accesses (i.e., whether they caused a fault and the value read).

We cannot use shared-memory barriers for synchronization among cores, as they introduce memory accesses that add undesired interference with the tests. Instead, we intend to leverage synchronized timestamp counters for synchronization. The test drivers agree on the timestamp counter value at which each core starts its execution.
